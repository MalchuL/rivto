# Ревью незакоммиченных интерфейсов Chulane

Дата: 2026-10-26. **Исторический отчёт:** модель personal/shared и `actorId` в методах пересмотрены решением от 2026-10-27. Область: текущие контракты `app/chulane/src`, их SQLite-реализации, HTTP и UI. Редакторные пакеты не затрагиваются.

## Выводы и решения до реализации

| Контракт | Пробел | Решение |
| --- | --- | --- |
| WorkspaceService | Есть `rename`, нет общей операции обновления метаданных | Заменить `rename` на `update(actorId, workspaceId, WorkspaceUpdate): Promise<Workspace>`. Сейчас изменяемо только имя; ID, personalOwnerId и статус удаления через update менять нельзя. |
| WorkspaceService | Нет удаления | Добавить `delete`. Любой owner может удалить shared workspace, даже если owners несколько. Personal workspace отдельно удалить нельзя. Проверка прав и запись выполняются одной транзакцией. |
| WorkspaceService | Безвозвратное удаление противоречит требованию восстановления | Сохранять `deletedAt` в миллисекундах UTC и участников. Исключать удалённое из обычных списков и операций; добавить `listDeleted` для прежних owners и `restore`. Повторное удаление сохраняет исходную отметку; восстановление возвращает прежние права. |
| IdentityService | Имя Chulane авторитетно, но изменить его можно только неявно через исходное auth-имя при создании | Добавить `update(actorId, UserUpdate): Promise<User>` для собственного имени. HTTP берёт actorId исключительно из сессии. Auth-имя, пароль и email не меняются. |
| LocalState | Составной workspace описан inline; нет данных для восстановления | Выделить `LocalWorkspace`, добавить `deletedWorkspaces`. Контракт остаётся в runtime/types.ts. |
| Pagination | Нет total/cursor | Не менять: текущим спискам достаточно limit/offset, новые протоколы не нужны для поставленной задачи. |
| ErrorNotifications | Есть только ошибки | Не менять: обязательного сценария для новых методов нет. |
| Cordis Context | Регистрация сервисов | Не менять: существующие сервисы уже подходят для новых операций. |

## Путь реализации

1. Регрессионные тесты: профиль, update workspace, права удаления/восстановления, personal workspace, повторные операции, откат и перезапуск; затем HTTP и браузер.
2. Именованные входные типы в соответствующих `types.ts`; нормализация имени и выбор разрешённых полей в сервисах.
3. По указанию пользователя начальная схема генерируется заново целиком, без обновления или сохранения старых данных. Включить deletedAt и запрет отметки удаления у personal workspace.
4. SQLite: tombstone сохраняет стабильный ID, участников и данные для восстановления. Каждый обычный lookup отсекает удалённые записи; владельцы получают отдельный список удалённых.
5. HTTP: update, delete, restore, update-profile с проверенными аргументами и действующим пользователем из сессии.
6. UI: изменение имени профиля, существующая форма переименования через update, диалог удаления с названием и последствиями, список удалённых с восстановлением. Ошибка удаления сохраняет диалог и данные.
7. Обновить все вызовы rename и фикстуры; выполнить type checks, lint, unit-тесты, build и браузерные/Electron-тесты.

## Границы

Удаление аккаунта не добавляется: необходимо отдельно определить судьбу shared ownership, учётных данных, сессий и будущего личного содержимого. Дополнительные поля workspace и профиля не выдумываются. Постоянного удаления и purge нет.

Проекты, страницы и документы пока отсутствуют в текущем приложении. Их физическое удаление не имитируется: будущие сервисы обязаны проверять доступность workspace, а восстановление должно сохранять их содержимое. Удаление сейчас локальное; существование tombstone само по себе не реализует сетевую синхронизацию.


## Результат реализации

Все перечисленные изменения реализованы: контракты и входные типы находятся в
`types.ts`, SQLite и HTTP поддерживают update/delete/restore/update-profile,
UI предоставляет формы и подтверждение удаления. Повторные lifecycle-операции
не меняют исходную отметку удаления; ошибка записи сохраняет прежнее состояние.
Подмена ID, ownership и deletedAt через update отсекается выбором разрешённых полей.

Начальная схема перегенерирована одним `0000_identity_workspaces.sql`; отдельной
миграции обновления старой схемы нет. Старые development-БД не сохраняются и не
поддерживаются.

Проверено: 21 unit/integration-тест; 10 браузерных и Electron-сценариев, включая
отмену удаления, отказ операции с открытым диалогом, повторную попытку,
восстановление после перезагрузки и сохранение имени профиля. Type checks, lint,
production build, Drizzle check и `git diff --check` прошли.
