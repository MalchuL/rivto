# Обзор незакоммиченных изменений Chulane — 28 октября 2026

Проверены staged, unstaged и неотслеживаемые файлы относительно HEAD. Начать стоит с корректности обновления форм, затем решить, должен ли собранный сервер запускаться из произвольного рабочего каталога. Исходная задача для всего набора изменений не предоставлена; соответствие оценивалось по текущим ADR, CONTEXT и документации приложения.

## Поведение и соответствие требованиям

1. **P2 — повторное переименование может перезаписать более новое имя workspace.** `app/chulane/src/components/local-workspaces.tsx:217`, `:225`, `:153`. Поле использует `defaultValue` и сохраняет DOM-элемент при обновлении состояния. Если другое окно или пользователь переименует workspace, а здесь состояние обновится после любой операции, заголовок покажет новое имя, но поле сохранит старое. Нажатие Rename вернёт старое имя без намеренного редактирования. Синхронизировать поле с актуальным именем с учётом несохранённого ввода; проверить сценарий двух окон и последующего обновления состояния. Это вывод по коду, браузерный сценарий отдельно не воспроизводился.

2. **P3 — расположение миграций зависит от рабочего каталога процесса.** `app/chulane/src/storage/sqlite/services.ts:66`. `resolve("drizzle")` ищет миграции в текущем каталоге, тогда как сервер находит корень приложения относительно своего модуля. Прямой запуск собранного хоста из корня репозитория (`node app/chulane/dist/src/runtime/server.js --port 0`) завершился ошибкой `Can't find meta/_journal.json file`. Документированные pnpm-команды и Electron запускают процесс из каталога приложения, поэтому их это не блокирует. Если прямой запуск или другой хост предполагается поддерживать, следует привязать путь к каталогу приложения и проверить запуск из другого cwd.

## Стандарты

1. **Документация методов сетевого слоя неполна.** Например, `app/chulane/src/infrastructure/network/http/service.ts:106` и `:128`: JSDoc перечисляет параметры и результат, но не объясняет поведение метода. Инструкция репозитория требует описывать назначение и семантику каждой функции и метода. Стоит отдельно пройти публичный API и описать существенные условия, включая ошибки и повтор после обновления авторизации.

Сетевые сервисы пока не подключены к runtime (`app/chulane/src/infrastructure/network/README.md`); это повод сверить их объём с исходным заданием, а не подтверждённый дефект.

## Как просматривать изменения

Из корня репозитория:

```bash
git status --short --untracked-files=all
git diff HEAD -- app/chulane/CONTEXT.md docs/adr dev_notes/chulane-reimplementation-plan.md
git diff --cached -- app/chulane
git diff -- app/chulane
```

Для `AM src/domain/identity/types.ts` сравнить обе стадии отдельно: `git diff --cached -- app/chulane/src/domain/identity/types.ts` и `git diff -- app/chulane/src/domain/identity/types.ts`. Новые неотслеживаемые файлы читать напрямую: они отсутствуют в обоих diff. Перед завершением ревью повторить `git status --short --untracked-files=all`, поскольку рабочее дерево может измениться.
