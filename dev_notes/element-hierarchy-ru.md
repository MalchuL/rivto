# Иерархия элементов и canvas

## Решение

Canvas содержит упорядоченные корни элементов. Элементы хранятся один раз в
общем реестре и содержат childIds. Принадлежность задаётся только списками
корней/детей; parentId и canvasId вычисляются индексом модели. Группы используют
эту иерархию вместо props.children. Координаты и zIndex сохраняют прежний смысл.

Модель владеет вставкой, перемещением, группировкой, разгруппировкой, удалением
поддеревьев, проверкой ссылок и согласованием структуры после CRDT-изменений.
Canvas доступен через editor.canvases.get(id), его операции — через .elements;
forCanvas удаляется. Общий реестр остаётся для чтения по ID и обслуживания
документа. Panel и canvas сохраняют прежнее назначение, история undo общая.

## Этапы

1. Канонические корни/дети, индекс родителей и canvas, структурные операции,
   snapshot и проверки document-model.
2. Canvas API core без forCanvas, сохранение существующего pipeline обработки.
3. Группировка, clipboard, трансформации и реконсиляция React через модель.
4. Обновление demo, fixtures, документации; unit/type/lint/build и browser checks.

Миграции старых данных не требуются. CRDT, snapshot, undo/redo, вложенные группы,
перенос между canvas и clipboard должны сохранять ID и согласованное владение.
Stage не менять. Предыдущие изменения Panel сохраняются.

## Проверки

Используется rivto-performance-testing. Baseline production demo сохраняется
в /tmp/rivto-element-tree/. Проверки структуры включают циклы, повторное владение,
потерянные ссылки, конкурентные операции, транзакции и изоляцию canvas.
Browser: группировка/разгруппировка, clipboard, Panel и edgeless в Chromium/Firefox.
Производительность: обычный demo и repeat=200, реальные действия, отдельно
синхронная работа и DOM, с проверкой результата; замеры выполняются последовательно.

## Реализованная модель

- Snapshot v8: `canvases[].rootElementIds` и `elements[].childIds` задают дерево.
  Вычисляемый `canvasId` доступен при чтении элемента, но отсутствует в snapshot.
- `DocumentElementManager` выполняет перемещение, группировку, разгруппировку и
  удаление поддеревьев транзакционно. Циклы и некорректные ссылки отклоняются до записи.
- `ElementHierarchy` строит индекс родителей и canvas только после структурных
  изменений. Изменение геометрии или props использует готовый индекс.
- При конкурирующих ссылках выигрывает первое размещение в обходе canvas,
  отсортированных по ID. Недостижимые записи сохраняются в корнях `main`;
  отсутствующие, повторные и циклические ссылки удаляются при нормализации.
- Core предоставляет `editor.canvases.get(id)?.elements`. Операции конкретного
  canvas используют общий pipeline и историю; перенос между canvas выполняется
  через общий `editor.elements.moveElements`.
- Группа хранит детей в `childIds`. React отвечает за геометрию и выбор объектов,
  а модель — за структуру. Координаты детей остаются относительно canvas.
- Clipboard сначала вставляет записи, затем восстанавливает дочерние связи по
  карте ID в той же транзакции. Snapshot и Review report сохраняют корни и детей.

Удаление родителя удаляет его поддерево; разгруппировка сохраняет детей на месте
родителя. Пустые группы допустимы в модели. Partial snapshot, заменяющий набор
элементов, должен также передавать согласованные корни canvas, если они изменились.
Предыдущие сохранённые данные не мигрируются.

## Вложенный API элементов

Следующий этап добавляет `ElementInput.children`, рекурсивный `DocumentElement`
(`EditorElement` в core) и плоский `ElementNode` (`EditorElementNode`).
`getElement`/`getElements` читают деревья, `getElementNode`/`getElementNodes` — узлы.
Внутренние читатели переведены на плоские методы, чтобы не материализовать деревья
при рендеринге, hit-testing, clipboard и сохранении данных.

Модель проверяет подготовленное дерево перед записью, вставляет его транзакционно
и сохраняет прежний snapshot v8. Непустая группа может не задавать frame: при
создании вычисляется объединение границ детей. Пустой группе frame необходим.
Кеш рекурсивных объектов сохраняет неизменённые ветви и инвалидирует предков
изменённого узла, включая старых и новых родителей при перемещении.

Рамки групп монтируются только для выделенных групп. Полная виртуализация canvas
не добавлена: существующая виртуализация работает с page roots, а canvas selection,
перетаскивание и коннекторы местами используют DOM смонтированных элементов.
Для безопасного удаления невидимых элементов из DOM потребуется отдельная работа
над этими зависимостями и геометрией. Текущий API не собирает рекурсивные деревья
для плоского рендеринга и не включает виртуализацию принудительно.
