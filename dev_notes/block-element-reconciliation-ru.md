# Реконсиляция элементов с блоками

Окончательное решение: сохраняем `startBlockId` и `endBlockId`, чтобы сопоставлять
элементы с содержимым. `rangeIndex` не вводим. `rootBlockId` и `rootElementId`
остаются настройками Panel, но больше не записываются в props элементов.

Реконсиляция читает элементы из области Panel и выбирает тип `block`. Принадлежность
блоков определяется их текущим положением в дереве, а не сохранённым владельцем.
Если одна граница удалена, область определяется по второй; если удалены обе,
элемент может быть удалён. Элементы с живыми границами вне текущей области блоков
не меняются. Остальные типы элементов не участвуют в реконсиляции.

Области могут пересекаться. У элементов нет независимого владельца-проекции:
реконсиляция сопоставляет существующие элементы с диапазонами текущей области.
Элементы, больше не соответствующие диапазонам, удаляются; их дети поднимаются
на место удалённого родителя. Дополнительный элемент, уже точно описывающий живой
диапазон, сохраняется: пересекающаяся область не должна удалять корректное
представление внутри более узкой Panel.

При вставке оба пути используют `copyElementProps`, сохраняя rotation, autoHeight
и пользовательские настройки. Общий helper исключает из копируемых настроек границы диапазона и прежние поля
корней. Ссылки на блоки задаются заново по результату импорта.
Сама реконсиляция обновляет только границы диапазонов, сохраняя остальные props,
геометрию и идентификаторы сопоставленных элементов.

Это заменяет описание принадлежности через props.rootElementId/rootBlockId
в предыдущем плане panel-element-roots-ru.md. Миграция старых данных не требуется.

## Проверки

- Регрессия потери rotation/autoHeight воспроизведена до исправления.
- Полный React Jest: 356 тестов; после последнего изменения clipboard повторены
  48 связанных тестов. Типы React, workspace lint и production demo build проходят.
- Браузеры: 60 сценариев Chromium/Firefox; после финальных правок повторены
  34 сценария Panel, иерархии элементов и выделения, workers=1, включая repeat=200.
- Реальное перетаскивание элемента с блоками внутри Panel, production Chromium:
  2 прогрева и 5 измерений, без параллельных тестов/сборок. Медиана синхронного
  history.batchUpdates: обычный документ 0,6 → 0,6 мс (после: 0,4–0,8);
  repeat=200: 0,8 → 0,9 мс (после: 0,8–1,0). От pointerup до двух кадров:
  30,2 → 29,6 мс (26,8–30,6), repeat=200: 30,4 → 30,6 мс (29,7–30,7).
  Каждый жест проверяет итоговые координаты. Два кадра — оценка отрисовки,
  а не гарантия завершения всех отложенных операций. Замер не измеряет вставку.

Полный workspace test/e2e не запускался. Stage оставлен без изменений.
