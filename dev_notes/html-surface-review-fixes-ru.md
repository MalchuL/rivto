# Исправления HTML-виджетов Rivto

Разбор девяти замечаний к ветке HTML-виджетов. Исходная версия для сравнения — `9afad8e2`. [Отчёт ревью](./html-surface-review-against-main.md)

## 1. Доступ к редактору после перехода внутри iframe

Ссылка или форма могла загрузить другой документ в тот же iframe. Браузер сохранял объект окна, а редактор после каждого события `load` отправлял в него снимок блока и токен. Для блока с разрешённым доступом выданное разрешение тем самым распространялось на страницу назначения.

Теперь исходный документ создаёт `MessageChannel` и передаёт один порт редактору. При установлении соединения редактор проверяет окно и токен текущего исходника. Снимки, команды и ответы идут через порт, оба конца которого принадлежат конкретным участникам соединения. При уходе со страницы виджет закрывает свой порт. При изменении исходника или разрешения редактор закрывает старый порт и выдаёт новый токен. Перед каждой операцией с блоками редактор также проверяет актуальное разрешение. [Соединение в редакторе](../packages/react-rivto-editor/src/extensions/html-surface/components/html-frame.tsx) · [Код внутри iframe](../packages/react-rivto-editor/src/extensions/html-surface/protocol/protocol.ts)

## 2. Потеря параллельных изменений при сохранении

Если другой участник добавлял свойство, пока открыт редактор HTML, кнопка Done удаляла это свойство. Редактирование только JSON также могло вернуть прежний HTML.

Форма запоминает исходные HTML и JSON на момент открытия. При сохранении она сравнивает их с черновиком. В модель попадают только изменённые поля верхнего уровня. Удаление ключа из черновика удаляет его из модели, а сохранение без изменений пропускает запись. Для элемента холста исходник хранится в `props.html`, поворот остаётся в ведении холста. Единица записи для вложенного JSON — всё значение соответствующего свойства. [Форма](../packages/react-rivto-editor/src/extensions/html-surface/components/html-chrome.tsx) · [Запись блока](../packages/react-rivto-editor/src/extensions/html-surface/components/html-block.tsx) · [Запись элемента](../packages/react-rivto-editor/src/extensions/html-surface/components/html-element.tsx)

## 3. Общий режим редактирования в двух панелях

Две панели одного редактора могли показывать один блок. Нажатие Edit HTML открывало две формы, а закрытие любой из них уничтожало оба черновика.

Ключ подписки теперь включает идентификатор панели, вид узла и его идентификатор. Кнопка и форма внутри одной панели по-прежнему видят общее состояние. Другая панель ведёт собственный сеанс. После отписки последнего наблюдателя запись удаляется. [Хранилище режима редактирования](../packages/react-rivto-editor/src/extensions/html-surface/hooks/use-html-editing.ts) · [Тест двух панелей](../packages/react-rivto-editor/src/extensions/html-surface/html-editing.test.tsx)

## 4. Перетаскивание перекрывало строку раскрытия

Браузер раскрывает `<details>` при нажатии на любую часть строки `<summary>`. Виджет исключал из области перетаскивания только текст. Нажатие на свободное место справа от заголовка доставалось редактору.

Теперь из области перетаскивания исключается весь прямоугольник `<summary>`. Та же обработка учитывает `<label>` и встроенные элементы управления аудио и видео. [Расчёт областей](../packages/react-rivto-editor/src/extensions/html-surface/protocol/protocol.ts)

## 5. Области перетаскивания оставались на старых координатах

В iframe фиксированной высоты раскрытие `<details>` сдвигало кнопку под ним. Размер самого iframe оставался прежним, а редактор продолжал перехватывать нажатия по новым координатам кнопки.

Мост учитывает изменение атрибута `open`, изменения размеров содержимого, загрузку ресурсов и шрифтов. Повод для пересчёта ставит задачу на ближайший кадр. Редактор получает новые прямоугольники при изменении их координат. Браузерный тест раскрывает секцию нажатием справа от текста, затем нажимает переместившуюся кнопку. [Реализация](../packages/react-rivto-editor/src/extensions/html-surface/protocol/protocol.ts) · [Проверка взаимодействия](../e2e/html-edit-session.spec.ts)

## 6. Виджет с пропущенным head запускал скрипт до инициализации API

Поиск `<head` принимал тег `<header>` в теле документа за начало заголовочной части. Скрипт перед ним мог обратиться к ещё не созданному `window.rivto`.

При подготовке `srcdoc` редактор читает начальную часть разметки, включая пробелы, комментарии, объявление типа документа и открывающие теги `html` и `head`. В этот момент он вставляет мост и оставляет дальнейший разбор HTML браузеру. Метод работает и при опущенном `head`. [Подготовка srcdoc](../packages/react-rivto-editor/src/extensions/html-surface/protocol/protocol.ts)

## 7. Готовый виджет ждал окончания загрузки ресурсов

Первый снимок мог быть отправлен до установки обработчика внутри iframe. Следующая отправка зависела от события `load`. Медленная картинка задерживала `rivto.ready()`, хотя скрипт уже работал.

Теперь обработчик сообщения `ready` принимает порт и сразу отправляет актуальный снимок с контекстом панели. Браузерная проверка удерживает запрос картинки открытым до появления данных виджета. Отдельно проверяются документы с явным и опущенным `head`. [Обработка готовности](../packages/react-rivto-editor/src/extensions/html-surface/components/html-frame.tsx) · [Проверка в браузере](../e2e/html-edit-session.spec.ts)

## 8. Удалённый обработчик продолжал блокировать перетаскивание

После временной подписки на щелчки живой элемент оставался в списке интерактивных областей. Снятие подписки, выполнение одноразового обработчика и отмена подписки через сигнал оставляли фон недоступным для перетаскивания.

Мост сопоставляет регистрации по типу события, исходному обработчику и флагу перехвата. При завершении последней регистрации он снимает исключение и запрашивает пересчёт. Связь сигнала с элементом хранится через слабые ссылки, чтобы долгоживущий сигнал не удерживал удалённый узел. [Учёт обработчиков](../packages/react-rivto-editor/src/extensions/html-surface/protocol/protocol.ts) · [Проверка трёх способов отписки](../e2e/html-edit-session.spec.ts)

## 9. Полноэкранный режим сбрасывал выделение и историю отмены

Переход между встроенной формой и диалогом создавал новое состояние CodeMirror из строки. Текст сохранялся, но после разворачивания пользователь терял выделение и возможность отменить предыдущую правку.

В течение сеанса форма хранит состояние CodeMirror отдельно для каждого поля. При смене представления старый вид освобождается, новый получает сохранённые документ, выделение и историю с обработчиком текущего представления. После закрытия формы эти состояния освобождаются вместе с черновиком. В браузерной проверке выделение сохраняется после разворачивания, отмена работает в диалоге, а повтор правки — после возврата во встроенную форму. [Поле CodeMirror](../packages/react-rivto-editor/src/extensions/html-surface/components/html-code.tsx) · [Проверка отмены и повтора](../e2e/html-edit-session.spec.ts)

## Проверка

- Пять браузерных регрессий воспроизвелись на исходной сборке Chromium и при параллельном запуске, и при повторе с одним рабочим процессом. Проверка изоляции двух панелей одного редактора также падала до исправления.
- В итоговой сборке Chromium и Firefox прошли сценарии навигации и повторной загрузки iframe, запуска при незагруженной картинке, работы с раскрывающейся секцией, освобождения областей перетаскивания, параллельного изменения блока и элемента, сохранения выделения и истории отмены.
- Прошли 21 тест в восьми затронутых наборах React и 31 тест демоприложения. Сборки React-пакета и демоприложения, проверка типов React-пакета прошли. ESLint сообщил о шести предупреждениях о длине функций, ошибок нет.
- В шести браузерных файлах при 12 рабочих процессах прошёл 141 тест. Один тест сборки мусора использует Chromium DevTools Protocol и пропущен в Firefox. Четыре запуска упали при проверке фокуса исходника в Edgeless. Это два сценария в каждом браузере. Все четыре сбоя повторились с одним рабочим процессом на исправленной сборке и на исходной сборке `9afad8e2`, в той же проверке после щелчка по полю CodeMirror.
- При проверке владения ресурсами прослежены создание и закрытие обоих портов, проверка разрешения перед обращением к менеджеру блоков, отписка последнего наблюдателя панели и уничтожение представлений CodeMirror. Форма владеет состояниями полей, каждое поле заимствует операции чтения и записи своего состояния. Модель получает изменения через менеджер текущей панели.

## Измерение производительности

В производственной сборке демоприложения нажатие кнопки внутри разрешённого Unsafe HTML изменяло соседний блок. Каждый замер проверял новый текст и ровно одну запись в модель. Между повторами изменение отменялось. Для каждого размера документа выполнены прогрев и пять измерений с одним рабочим процессом. В таблице показаны медиана и диапазон в миллисекундах.
