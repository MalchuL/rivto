# Moveable и динамические группы

## Согласованный план

Moveable — единственный источник видимых рамок и контролов трансформации.
Удаляем дополнительное CSS-выделение фигур и карточек и неиспользуемый
applyRotatedResize. Обычные границы карточек, выделение текста, коннекторов и
marquee остаются. Создание объектов сохраняет существующие привязки и направляющие.

Угол группы хранится в props.rotation (по умолчанию 0). Размеры и центр непустой
группы вычисляются по углам прямоугольников конечных детей в осях группы.
Положение ребёнка меняет рамку, но не угол и не геометрию остальных детей.
Сохранённый frame нужен только пустой группе. Специальной сущности в core нет.

Общий расчёт React-расширения используется контролами, hit area, коннекторами и
программными операциями. Различаем ориентированный frame с rotation и внешний
прямоугольник вдоль осей canvas. Никаких фоновых записей производных границ.

Во время жеста исходные left/top и центр вращения стабильны; предпросмотр
использует трансформации Moveable. При завершении сохраняем геометрию детей и
углы вложенных групп одним undo-шагом. Escape отменяет предпросмотр. Moveable
получает defaultGroupRotate, useDefaultGroupRotate и flushSync. Группа с одним
ребёнком сохраняет свой угол через публичный persistData.

Ресайз групп мышью всегда пропорциональный. Одиночные элементы меняют пропорции
свободно, Shift ограничивает их. Шрифты и толщина линий не масштабируются.
Числовой API resize(width, height) сохраняет контракт и работу без DOM.
Контейнер Panel исключён из выбираемого поддерева.

## Проверка

Воспроизвести потерю угла до исправления. Проверить смешанные углы, непрерывный
поворот и обратный поворот, перемещение детей, вложенные/пустые группы и одного
ребёнка, перенос между группами, удаление, clipboard, snapshot, undo/redo,
перемонтирование, ресайз, рисунки, HTML-карточки и коннекторы.
Запустить тесты Chromium/Firefox последовательно и production-замеры реальных
жестов на обычном документе и repeat=200. Stage не изменять.

## Реализация и уточнение точности

Расчёт сосредоточен в ElementGeometry: frame возвращает прямоугольник до
поворота, bounds — его внешние границы вдоль осей canvas. Подстановка предпросмотра
позволяет тем же расчётом обновлять коннекторы и hit area без записей в документ.
Вложенные углы сохраняются вместе с изменёнными листьями; пустые группы сохраняют
frame, поскольку у них нет детей, из которых можно получить положение.

Проверка поворота на +10° и обратно выявила около 0,1 px сдвига из-за округления
DOM offsetLeft/offsetTop при дробных CSS left/top. Поэтому HTML-элементы теперь
используют left/top=0 и абсолютный translate(x,y) перед rotate. Moveable получает
эту же начальную трансляцию. Коннекторы сохраняют позиционирование своего SVG
контейнера, а координаты свободных концов преобразуются отдельно. Это позволяет
использовать события rotateGroup без собственной формулы перемещения детей.

Старые браузерные проверки координат теперь учитывают CSS-матрицу, а проверки
непрерывного поворота измеряют реальные центры DOM-элементов. Тесты больше не
принимают неподвижные left/top за положение изменяемого объекта.

## Результаты проверки

- Исходная сборка: новый тест терял угол группы (props.rotation отсутствовал).
- Промежуточная реализация: обратный поворот обнаружил сдвиг около 0,1 px;
  после перехода HTML-позиций на translate тест проходит с точностью 0,00005.
- 208 выполненных браузерных сценариев прошли в Chromium и Firefox, workers=1.
  Проверялись весь edgeless.spec.ts, Moveable, группы, ресайз и Panel. Старый
  отключённый тест отменённого поведения bbox удалён; действующие проверки
  попадания в промежуток группы сохранены.
- 354 модульных теста React прошли (полный прогон и точечные проверки последних
  добавлений), типы React, lint и production-сборка demo успешны.
- Проверка на тысяче посторонних элементов подтверждает, что вычисление рамки
  читает только запрошенное поддерево. Git index не изменён.

Production Chromium, 1440×1000, настройки demo по умолчанию. Реальный поворот
группы на 90° за 12 движений мыши; два прогрева, пять измерений, последовательные
запуски исходной и итоговой сборок. Проверены расстояния между детьми, конечный
поворот, отсутствие оставшихся блокировок предпросмотра и сохранение угла группы.
Значения — медиана [минимум–максимум], миллисекунды.

| Документ   | Commit до     | Commit после  | Два кадра после отпускания до | После               |
| ---------- | ------------- | ------------- | ----------------------------- | ------------------- |
| Обычный    | 0,7 [0,7–0,8] | 0,8 [0,6–0,9] | 28,8 [27,7–29,0]              | 29,2 [28,7–29,7]    |
| repeat=200 | 1,6 [1,4–1,6] | 1,6 [1,6–1,8] | 123,2 [121,3–147,8]           | 124,7 [121,7–159,5] |

Синхронная обработка одного mousemove: обычный документ 1,15 → 1,3 мс,
repeat=200 — 1,5 → 1,8 мс. В итоговой версии flushSync выполняет синхронизацию
контролов в этом же событии. Два кадра — показатель отрисовки, а не гарантия
завершения всех фоновых задач. Большая стоимость завершения на repeat=200
наблюдалась и до изменения; общую перерисовку большого документа здесь не
оптимизировали. Полный набор остальных пакетов и все e2e workspace не запускались.
