# Конвертеры clipboard для блоков и элементов

Согласованный план: тип управляет своими данными и переносимым представлением;
clipboard управляет ID, иерархией, размещением, выделением и undo.

## Регистрация и контракт

- `clipboard` в `ReactBlockRegistration` / `blockExtension`.
- `runtime.clipboard.registerBlockConverter(type, converter)` и
  `registerElementConverter(type, converter)`; одна регистрация на тип, disposer
  и очистка вместе с расширением. Отдельный реестр типов элементов не вводим.
- Необязательные синхронные методы `copy`, `paste`, `format`, `parseHTML`,
  `parseText`; у элементов `getReferencedBlockIds` собирает связанные блоки.
- Методы получают отделённые данные; назначение ID и перестройка дерева остаются
  общими. Контекст вставки содержит карты ID обоих видов, документы, принимающий
  view, смещение canvas и операцию paste/duplicate. Конвертер не пишет документ.
- Без метода сохраняется обычное копирование; неизвестным элементам не выдумываем
  текст из произвольных props.

## Карты ID, запись и очистка при ошибке

- Двухэтапный API prepareImportForest/insertPreparedForest удалён по решению пользователя.
  Для элементов также удалены prepareInput/insertPreparedElement, введённые для clipboard.
- Конвертеры получают карты будущих ID. Обычный importForest принимает эту карту
  последним необязательным аргументом, выполняет процессоры и вставляет блоки;
  элементы записываются обычным insertElement.
- Запоминаются новые ID блоков и элементов; canvas-стратегия добавляет в этот список
  ID создаваемых разделителей и дополнительных карточек. При ошибке созданные
  записи удаляются, прежнее выделение восстанавливается, ошибка передаётся вызывающему.
- Очистка выполняется в том же history batch. Существующий первый блок при вставке
  в текстовый диапазон не удаляется. Изменения/удаления существующего текста и
  произвольные побочные эффекты сторонних стратегий не откатываются этой очисткой.
- Copy, Cut, Paste и оба Duplicate используют общие конвертеры. Cut сначала готовит
  представления. Ссылки connector и диапазоны block переписываются конвертерами.
- startBlockId/endBlockId во внутреннем clipboard обозначают исходный диапазон;
  root-поля и rangeIndex не возвращаются. Core не получает DOM или React-конвертеры.

## Переносимые форматы

- Расширить существующий ClipboardFormatRegistry: сначала формат типа, затем
  общие форматтеры (например, свойства списков).
- HTML разбирается в отдельном DOM-документе. Конвертер принимает отдельный узел
  целиком либо возвращает undefined. Не терять соседние абзацы и вложенность.
- Парсеры типов — в порядке регистрации, общий разбор — последним. Существующие
  парсеры целого буфера выполняются перед обходом фрагментов.
- Внутренний формат приоритетнее; plain-text paste обходит конвертеры.
- Page вставляет реальные блоки карточки block напрямую, остальные элементы —
  через HTML/text. Группы обходят детей по порядку, блоки не дублируются.
- Edgeless сохраняет внутренние элементы; внешний парсер может создавать элементы.
- Перенести существующие форматтеры типов. Добавить примеры для стикера,
  canvas-текста и Counter. Входной HTML не монтировать непосредственно в редактор.

## Реализованный API и точки входа

Регистрации находятся в `src/managers/clipboard/clipboard-converters.ts`. Блок
может передать `clipboard` рядом с `definition` и `render` в `blockExtension`.
Пример интеграции — Counter в `demo/src/blocks/custom-blocks.tsx`: он экспортирует
HTML с маркером типа, распознаёт свой HTML и текст `Count: 42`.

Для элемента регистрация выполняется в `setup` расширения:

```ts
setup(editorRuntime) {
  return editorRuntime.clipboard.registerElementConverter("my-element", {
    copy(element) {
      const props = { ...element.props };
      delete props.temporaryState;
      return { props };
    },
    paste(element, { elementIdMap }) {
      const props = { ...element.props };
      const target = elementIdMap.get(String(props.targetElementId));
      if (target) props.targetElementId = target;
      else delete props.targetElementId;
      return { props };
    },
  });
}
```

`copy`/`paste` получают отделённые записи. Блок содержит `childIds`, а не повторную
копию всего поддерева. Возвращаются только изменяемые поля: для блоков — content,
props, listProps, pluginData; для элементов — props. Пропущенное поле сохраняется.
Удаление свойства выполняется возвращением нового объекта props без этого ключа.
Менять документ внутри конвертера нельзя.

`parseHTML` принимает целое поддерево HTML; `undefined` передаёт его следующему
парсеру, `{}` поглощает узел без вставки. На Page возвращаются blocks, на canvas
допускаются elements. HTML разбирается в отдельном документе и не монтируется.
Текст сохраняет `<br>`, общий разбор поддерживает вложенные списки. Произвольный
HTML не получает полной визуальной совместимости с браузерной страницей.

`format` возвращает plain, markdown и html. Сначала выполняется форматтер типа,
после него общие форматтеры свойств списков. Неизвестный элемент без собственного
форматтера сохраняется во внутреннем формате, но не получает выдуманного текста.

`getReferencedBlockIds` у элемента перечисляет блоки, переносимые вместе с ним.
Это не список произвольных внешних ссылок: canvas Cut удаляет переносимые исходные
блоки вместе с элементами. У карточки block сюда попадает её диапазон. Пустые
карточки, чей диапазон отсутствует в буфере, не вставляются и отсутствуют в карте ID.

Основной путь — `editorView.clipboard` и `editorRuntime.clipboard`. Низкоуровневый
`coreEditor.clipboard` остаётся независимым от React и **не вызывает** конвертеры
React-типов. Программный код, которому они нужны (включая embeddings), использует
React-менеджер. У runtime-вызова без смонтированного view контекст editorView
отсутствует; документ, карты ID и операция при этом доступны.

В `visuals/controller.ts` и в slash-команде `block.duplicate` Duplicate вызывает
тот же менеджер. Собственные native
copy/paste-обработчики visuals удалены: браузерный clipboard подключается общим
clipboard-расширением, входящим в стандартный preset.

Core использует обычный importForest с необязательной картой уже выделенных ID.
Сложного механизма отката нет: React clipboard удаляет записи, созданные этой
вставкой. Это относится к структурированным данным конвертеров и служебным
карточкам/разделителям; внешние действия произвольного расширения не отслеживаются.

## Порядок ревью

1. `clipboard-converters.ts`: контракт методов и их жизненный цикл.
2. `clipboard-manager.ts`: сбор данных, ID и конвертация данных и очистка после ошибки.
3. `elements/clipboard-converters.ts`: block, connector и переносимый текст фигур.
4. `clipboard-format-registry.ts`: экспорт и обход внешнего HTML.
5. Core `block-manager.ts`, `element-manager.ts`, `paste-strategies.ts`: обычный импорт
   с заранее выделенными ID и однократным запуском процессоров.
6. Native `extensions/built-ins/clipboard/clipboard.ts` и Duplicate в visuals.
7. `clipboard-converters.test.ts` и `e2e/clipboard-converters.spec.ts`.


При измерении canvas-вставки обнаружен и исправлен дополнительный дефект общей
стратегии: буфер с elements и пустым blocks повторно вставлял text/plain как блоки.
Теперь внутренние элементы имеют приоритет над текстовым fallback; regression-тест
проверяет отсутствие лишних блоков, а браузерный бенчмарк проверяет также undo,
число элементов, иерархию группы и смещение координат.
