# Panel: корни блоков и элементов

## Решение

Panel — принадлежащая приложению запись `{ id, documentId, rootBlockId, rootElementId }`.
Оба корня nullable: null выбирает корни соответствующего дерева документа;
ID выбирает детей указанного узла. Корневой элемент служит контейнером и сам
не входит в выборку Panel. Несколько Panel могут ссылаться на одни корни.

В документе один реестр элементов, один упорядоченный список rootElementIds,
у элементов — childIds. Отдельные записи Canvas и canvasId удаляются.
Независимое расположение создаётся явно: группа элементов + rootElementId.
Открытие блока с null не создаёт группу и не меняет корень Panel автоматически.

## Реконсиляция

Существующий алгоритм разделения блоков по separator и сопоставления карточек
сохраняется. Проекция привязана к паре корней, выполняется при подключении вида
и после изменений. Одинаковые пары используют одну проекцию с подсчётом
потребителей. Проекция документа действует всё время жизни runtime.

Карточки разных участков блоков могут находиться в одном дереве элементов.
Каждая проекция изменяет только свой участок. Карточка хранит rootElementId в props как указание независимой проекции: оно
действует, пока эта группа остаётся предком. Это не второй источник родительства.
Карточка хранит rootBlockId в props
для случая удаления/разделения границ; существующие границы с общим текущим
родителем позволяют определить новое расположение после переноса блоков.
View фильтрует карточки по участку блоков, но обычные рисунки в выбранном дереве
остаются общими. Явно выбранная группа ограничивает чтение и операции элементов.

Сохраняем ID, координаты и свойства подходящих карточек. Удаление корневого блока
или элемента не должно превращать Panel в представление всего документа:
она остаётся пустой до undo. Реконсиляция не входит в историю пользователя.

## Изменения и проверки

- Document-model: корни, дерево, кеш, транзакции, snapshot новой версии.
- Core: API элементов и доступ к поддереву; без CanvasManager.
- React: Panel, владение проекциями, фильтрация карточек, clipboard и выборка.
- Demo/БД: новые snapshot и Panel; breadcrumb продолжает использовать block root.
- Тесты: обе null-ссылки, явная группа, общие/разные Panel, перенос карточек,
  удаление корней и undo, snapshot/clipboard, ограничение записей выбранной группой.
- Проверки типов, lint, unit, браузеры Chromium/Firefox; открытие Panel на обычном
  и repeat=200 документе в production до/после. Stage не меняется.

Обратная совместимость старой схемы не поддерживается согласно AGENTS.md.

При открытии явного rootElementId существующие карточки внутри него без отдельного
действующего контейнера проекции принимаются выбранной Panel: их ID и геометрия
сохраняются, props обновляются. Карточки другой вложенной независимой группы не
перехватываются. Так ранее сгруппированные или загруженные элементы не требуют
ручного заполнения служебных свойств для первого открытия.

### Открытие Panel: до/после

Production Chromium, 1440×1000, настройки demo по умолчанию, без принудительной виртуализации. Реальный клик по drag handle и возврат через breadcrumb. Два прогрева, пять повторных открытий; загрузка страницы и подготовка документа вне замера. Проверяется, что нужный дочерний блок показан как корень страницы. Конкурирующих тестов/сборок во время замера нет.

Синхронный замер охватывает активацию проекции (`acquireCanvas` до / `acquirePanel` после), включая её синхронных подписчиков. Это не весь React-render. DOM-время отсчитывается от pointerdown до появления нужного поддерева и двух animation frames.

| Документ   | Активация до, мс | Активация после, мс |          DOM до, мс |       DOM после, мс |
| ---------- | ---------------: | ------------------: | ------------------: | ------------------: |
| repeat=0   |    0.1 (0.0–0.2) |       0.0 (0.0–0.1) |    30.6 (30.0–30.8) |    30.8 (30.5–31.0) |
| repeat=200 |    0.1 (0.0–0.1) |       0.1 (0.1–0.2) | 170.7 (156.4–182.0) | 170.3 (154.8–179.1) |

Указаны медиана и диапазон. Субмиллисекундные значения зависят от разрешения таймера; они не доказывают ускорение. Сопоставление относится к повторному открытию прогретой Panel. Первое открытие, создание карточек и восстановление после удаления покрыты поведенческими тестами.

### Совместимость

Snapshot теперь v9: `rootElementIds` вместо `canvases`. Старые snapshot отклоняются без автоматической миграции. Clipboard остаётся v4 с плоскими записями; служебные ссылки карточек при вставке задаются для принимающей Panel.

## Исправление открытия Panel: отдельная группа элементов

При открытии внутреннего блока demo теперь создаёт обычную пустую группу и
сохраняет её ID в `Panel.rootElementId`. `EditorPanel` по-прежнему принимает
явно заданные корни: создание группы относится к навигации приложения.
Реконсиляция создаёт карточки внутри этой группы. Повторное открытие блока и
возврат по breadcrumb используют прежнюю запись Panel, группу и координаты.
Открытие исключено из undo. Основная Panel сохраняет `rootElementId: null` и
доступ ко всему дереву, включая группы внутренних Panel.

Обход родителей при выборе, перетаскивании и привязке коннектора останавливается
перед контейнером Panel: сам контейнер не входит в отображаемое поддерево.
Иначе первый клик по фигуре пытался выбрать недоступный корень вместо фигуры.

Записи Panel в demo живут только до размонтирования приложения. Для сохранения
навигации между запусками приложение должно сохранять оба корня вместе с Panel;
документ сохраняет элементы, но не восстанавливает записи навигации автоматически.

Проверки: обе ошибки воспроизведены падающими браузерными проверками до исправления.
После исправления прошли 70 сценариев Panel/Moveable в Chromium и Firefox с одним
worker, 41 модульный тест, проверка типов React, lint и production-сборка demo.

Замер реального клика по page drag handle: production Chromium, 1440×1000,
настройки demo по умолчанию, два прогрева и пять измерений, запуски последовательно.
В таблице медиана [минимум–максимум], миллисекунды. Синхронная часть измерена от
capture до окончания всплытия click; DOM — до двух animation frames, с отдельной
проверкой открытой Panel, видимого дочернего блока и созданной группы.

| Документ   | Обработчик до       | Обработчик после    | DOM до              | DOM после           |
| ---------- | ------------------- | ------------------- | ------------------- | ------------------- |
| Обычный    | 8,8 [8,4–12,1]      | 9,6 [9,2–10,7]      | 29,6 [27,5–30,3]    | 30,0 [29,1–30,6]    |
| repeat=200 | 130,4 [128,0–138,5] | 145,6 [138,7–149,7] | 133,2 [130,6–141,2] | 148,9 [141,4–153,8] |

Создание отдельной группы добавляет работу с документом; на большом документе
замер показывает около 15 мс дополнительной задержки. Общую стоимость
переключения больших Panel эта правка не оптимизирует. Полный набор тестов
workspace не запускался. Git index сохранён без изменений.
