# Управляемое размещение контролов BlockItem

`controlsPlacement="inside"` переводит общий left-top слот и его кнопки в поток
строки перед контентом. По умолчанию `outside`. Значение сопоставляется с ID
владельца строки, поэтому вложенные блоки не наследуют режим карточки.
`BlockDropWrapper` передаёт свойство в существующий `BlockItem`.

Bento включает режим у плиток, Columns — у содержимого колонок, Kanban — у карточек.
Настройка описана в `packages/rivto-page/README.md`.

Проверен путь layout → item/drop wrapper → локальный context → BlockRow → общий
CSS слота. Контекст хранит только ID и режим, memoized по этим значениям; данные
документа, lifecycle менеджеров и регистрации слотов не передаются через него.
BlockItem потребляет свойство до передачи native DOM-атрибутов. Дополнительные
DOM-обёртки и подписки для размещения не создаются.

Проверки: 46 unit-тестов; 126 браузерных тестов Chromium/Firefox, workers=12,
Page/Edgeless. Покрыты границы кнопок, отсутствие сдвига текста при hover,
изоляция вложенной строки, collapse/expand, меню, selection и существующий DnD.
Первый новый browser-прогон и serial-повтор (workers=1, timeout=5s) выявили
неверное accessible name collapse в тесте; после исправления теста весь набор прошёл.
Page build, demo TypeScript/Vite build, focused ESLint и Prettier прошли.

## Исправление живого демо и контролов колонок

В dev-демо 5173 подтверждено: DOM уже содержал inside, но отданный CSS не содержал
правил размещения. React stylesheet импортировал кешированную сборку Page из
package export. Демо теперь компилирует Page source CSS отдельным entry, потому
что Page использует Tailwind prefix page, а host — непредварённые классы. Vite
transform убирает только дублирующий compiled import из host source stylesheet;
публичный stylesheet пакета сохраняет свой импорт. Отдельный HMR probe подтвердил
обновление Page source CSS без перезагрузки страницы; временный probe удалён.

Columns размещает сами колонки через BlockItem inside, с flex-размерами на item.
Общее правило для пустых structural anchors больше не делает inside-строки
absolute: контролы колонки имеют собственную высоту перед первым ребёнком.
На живом демо оба handle внутри границ, в разных строках; исходно координаты
совпадали. Вложенные текстовые блоки сохраняют свои отдельные controlsPlacement.

Новый тест воспроизвёл наложение во всех четырёх browser/surface сочетаниях на
старой production-сборке, включая serial повтор. После исправления: 32 проверки
на dev 5173, 130 на production, Chromium/Firefox workers=12. Дополненный тест
подтвердил drag колонки (а не ребёнка) и Escape в четырёх сочетаниях. Build Page,
demo TypeScript/Vite, focused ESLint, Prettier и diff check прошли.

Повторный замер: реальный collapse колонки в обычном демо и repeat=200, два прогрева
и три пробы, persisted state и исчезновение ребёнка проверяются, expand между
пробами. Production, последовательные прогоны. Медиана [min–max], мс; два кадра —
proxy отрисовки. Короткая серия не устанавливает статистическую значимость.

## Регрессии первого входа и возврата к handle

`e2e/block-handle-activation.spec.ts` добавляет 48 browser-сценариев:
paragraph/Bento/Columns/Kanban × Page/Edgeless × Chromium/Firefox × три пути:

- первый прямой вход в handle без предварительного hover строки;
- потеря pointer ownership и blur/focus, затем первое нажатие без движения;
- уход указателя, blur/focus и один прямой вход обратно в handle.

Успех требует начала drag именно source, одной preview, сохранения вложенного
ребёнка, появления drop-линии, фактического переставления siblings и undo.
Геометрия кнопок, стабильность текста, collapse/menu и раздельные handles колонки
и её первого ребёнка остаются в `e2e/container-layout.spec.ts` (32 случая).

На production 5865: 24 новых случая прошли, 24 падают. 16 падений — первый press
после сброса hover не начинает drag; ещё восемь — Columns начинает drag, но у
нижнего края последнего target нет линии вставки. Каждая группа повторена
с workers=1 с тем же результатом. Прогон обеих suites на живом dev 5173,
workers=12: 56 passed / 24 failed. Ошибки не скрыты через skip или expected-fail.
Focused ESLint, Prettier и diff check прошли.

Граница проверки: lifecycle-события в новых тестах синтетические, мышиные нажатия,
движение и отпускание выполняет Playwright. Нативную смену окна ОС достоверно
воспроизвести не удалось: обычные новые страницы/bringToFront не давали ожидаемой
потери document focus, а desktop-пробы не подтвердили полный цикл trusted
blur/focus. Эти пробы не считаются проверкой пользовательского OS-сценария.
Тесты фиксируют воспроизводимую комбинацию pointerleave/blur/focus, а не доказывают,
какую именно последовательность отправляет конкретный оконный менеджер.

В этом шаге добавлены тесты и отчёт; runtime не менялся, поэтому повторные
production-замеры производительности неприменимы. Два обнаруженных дефекта
оставлены воспроизводимыми для следующего исправления.

## Первый press при возвращении из другого приложения

Уточнение пользователя: переключение внутри Chrome работает; сбой возникает при
возврате из другого приложения. Выявленный путь в Rivto: pointerleave снимает
маркер строки, CSS запрещает pointer events скрытой кнопке, поэтому press до
следующего pointermove попадает мимо handle. Теперь собственный прямоугольник
кнопки сохраняет pointer-events:auto, а :hover показывает кнопку независимо от
маркера строки. Размеры кнопок и областей слотов не менялись; новых слушателей
focus, зависимостей и публичных API нет. Проверены общий BlockHandle/DragHandle,
CSS слотов и управление hover в Page; lifecycle и владение ими не менялись.

В activation suite добавлен отдельный первый click (реальные mouse.down/up без
наведения между сбросом hover и нажатием), который должен открыть source в панели.
Проверка начала drag после сброса теперь изолирована от выбора назначения:
проверяет native hit target, начало drag и Escape. Перестановка и undo остаются в
двух остальных сценариях. Это отделяет дефект активации от известного дефекта
линии вставки Columns, не убирая проверку перестановки.

Dev: 72 passed / 8 failed, workers=12; восемь прежних Columns destination failures
повторены с workers=1. Production: 146 passed, Chromium/Firefox, workers=12:
activation (кроме этих восьми известных destination failures), container-layout,
block-row-hover, drop-boundary-regressions. Demo TypeScript/Vite build, focused
ESLint, Prettier и diff check прошли.

Production-замер реального drag/drop: обычное демо и repeat=200, по два прогрева и
три пробы, persisted порядок проверяется, undo между пробами. Workers=1, сборки и
тесты не пересекались с замером. Медиана [min–max], мс:

| Браузер / размер   | Команда до → после            | Pointerup до двух кадров до → после  |
| ------------------ | ----------------------------- | ------------------------------------ |
| Chromium / обычный | 0.8 [0.7–0.9] → 0.9 [0.9–1.0] | 28.6 [27.8–29.5] → 29.3 [29.2–30.1]  |
| Chromium / 200     | 3.5 [3.4–3.8] → 3.3 [2.9–3.3] | 75.9 [72.7–141.5] → 79.3 [66.8–83.5] |
| Firefox / обычный  | 1 [1–2] → 1 [1–2]             | 27 [27–27] → 28 [28–28]              |

Короткая серия не доказывает статистическую эквивалентность. Синхронная стоимость
команды существенно не выросла; диапазоны больших документов пересекаются.

Ограничение: цикл нативной активации ОС по-прежнему не подтверждён. Computer-use
в текущем Linux окружении сообщает windows.focus=false. Тест доказывает приём
доставленного браузером press после потери hover, но не доказывает доставку
первого клика оконным менеджером. Проверка пользователя в реальном окне нужна,
прежде чем объявлять весь его OS-сценарий исправленным.

Контроль нового click-теста на исходной production 5865: обычный paragraph в Page
не открывается первым нажатием после сброса hover в обоих браузерах; 2 failed с
workers=12 и 2 failed с workers=1. Подготовка специально прогревает row и handle
до сброса, чтобы исключить отдельный дефект cold hover. На исправленной сборке
все 16 click-сценариев повторно прошли после этого уточнения подготовки.

## Щели вокруг перетаскиваемого среднего блока

Сценарий: три обычных siblings, drag среднего, указатель чуть выше и ниже его
сохранённого места. Прежний listGap пропускал moving source и всегда выбирал
предыдущий stationary item. Поэтому нижняя щель показывала верхнюю линию и могла
проецировать вставку относительно верхнего блока. Теперь после пропуска moving
items сравниваются расстояния до ближайших неподвижных границ с обеих сторон.
Обычный путь без пропущенного source сохраняет прежнюю depth projection.
Изменение локально для BlockOutlineDropTargets; публичные API, владельцы объектов,
подписки и модель документа не менялись. Дополнительно измеряются максимум две
границы; обход поддеревьев не добавлен.

Новый e2e/drag-source-gaps.spec.ts проверяет реальный drag, обе линии на разных X
(ручка, край строки, текст), отсутствие inside-outline и сохранение sibling order
и parent при отпускании в исходной щели. Root/nested × Page/Edgeless × два браузера:
8 падений до изменения с workers=12, те же 8 с workers=1. После пересборки Page
8 passed на dev 5173. Production: 138 passed с workers=12 (новый сценарий,
drop-boundary-regressions, page-drag-container-boundary, page-nested-drag,
page-pointer-drag, container-layout). 27 unit tests прошли, включая один и три
соседних moving source. Page build и demo TypeScript/Vite build прошли; Prettier,
diff check и ESLint без ошибок (сохранилось предупреждение длины containerGap).

Production pointer benchmark: default demo и repeat=200, без изменения
виртуализации. Drag проходит нижнюю щель source, затем переставляет source после
следующего блока; persisted порядок проверяется, undo между пробами. Два прогрева,
три измерения; последовательные запуски без других tests/builds. Медианы до → после
в мс, синхронный pointermove в нижней щели / два кадра после него / move command:

- Chromium default: 0.4 → 0.5 / 16.9 → 16.9 / 0.8 → 0.8.
- Chromium repeat=200: 3.7 → 3.9 / 31.0 → 29.8 / 3.4 → 2.9.
- Firefox default: 1 → 0 / 18 → 16 / 1 → 1.
- Firefox repeat=200: 2 → 3 / 78 → 79 / 10 → 10.

Диапазоны sync pointermove на больших документах: Chromium 3.4–3.8 → 3.7–4.2,
Firefox 2–3 → 2–3 мс. Два кадра Firefox до изменения 9–82, после 79–79 мс:
это шумная proxy-метрика, не доказательство регрессии или ускорения. Восемь ранее
известных Columns destination failures и нативная активация окна ОС в этой правке
не проверялись и не исправлялись.
