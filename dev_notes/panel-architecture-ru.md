# Panel: поддерево документа с независимым canvas

## Согласованное поведение

Panel хранится приложением: `id`, `documentId`, `rootBlockId: string | null`,
`canvasId: string | null`. Null canvas выбирает основной canvas документа.
Canvas имеет собственный ID и закреплён за одним корнем блоков; один блок может
иметь несколько canvas. Блоки общие, элементы и расположение независимы.

В Panel показываются дети корневого блока. Сам корень используется как название
в demo. Существующий embedding продолжает показывать сам блок с потомками.
Приложение определяет открытие через callback; demo заменяет текущую Panel и
показывает breadcrumbs. Повторный переход использует прежние Panel и canvas.

## Реализация

1. Добавить канонические canvas и принадлежность элементов в document-model;
   валидацию, scoped-подписки, snapshots новой версии, CRDT и history scopes.
2. Дать core менеджер canvas и операции элементов выбранного canvas. Операции
   проверяют принадлежность до записи; удаление canvas не удаляет блоки.
3. Адаптировать BlockElementProjection: один владелец на canvas, диапазоны по
   детям rootBlockId, сохранение координат/ID/групп, отсутствие влияния на другие
   canvas. Неактивные canvas актуализируются при открытии.
4. Добавить EditorPanel, editorView.elements, проверку пары корней и ограничение
   редактирования. Перевести edgeless, clipboard, selection, geometry и создание
   карточек на область canvas. ID и ссылки при вставке переназначаются вместе.
5. Добавить открытие по одиночному клику drag handle конкретного блока, исключив
   завершение/отмену drag; не выбирать произвольный блок для multi-block карточек.
6. Добавить demo: title, breadcrumbs, возврат, сохранение canvas и режима Panel,
   пустой список детей, отсутствующий корень и восстановление через undo.

История общая. Удаление корня сохраняет canvas для undo. Основной canvas нельзя
удалить отдельно. Группы и соединения принадлежат одному canvas. Новая иерархия
элементов, приложение/БД, независимый undo и миграция старых snapshots не входят.

## Реализовано

Все шесть этапов выполнены. Публичный контракт и пример использования:
[panels.md](../packages/react-rivto-editor/docs/panels.md).

Основные места реализации:

- `packages/document-model/src/core/managers/canvas-manager/`: записи canvas,
  удаление вместе с элементами, включение в общую историю и snapshot v7.
- `packages/document-model/src/core/managers/element-manager/`: индекс элементов
  по canvas, стабильные snapshots и адресные уведомления. Загрузка snapshot с
  изменением canvas уведомляет подписчиков и старого, и нового владельца.
- `packages/rivto-editor-core/src/managers/element-manager/canvas-elements.ts`:
  операции одного canvas поверх существующего pipeline.
- `packages/react-rivto-editor/src/editor-view/panel.tsx`: EditorPanel и Panel;
  `EditorViewController` предоставляет элементы, верхний уровень и режим view.
- `EditorRuntime.acquireCanvas` и `BlockElementProjection`: общий владелец
  реконсиляции каждого используемого canvas, без сброса существующей геометрии.
- React edgeless/clipboard/selection/navigation: операции получают canvas и
  границы поддерева от view. При вставке групп переназначаются дочерние элементы
  и соединения; Enter и дублирование учитывают верхний уровень Panel.
- `demo/src/editor-panels.tsx`: переходы, breadcrumbs, название, повторное
  использование Panel и canvas. Enter на handle открывает Panel, Space запускает
  keyboard drag. Перетаскивание и его отмена не открывают Panel.

Дополнительно исправлено сохранение начального CRDT-состояния в demo: incremental
updates после создания main canvas зависят от его clock. Формат Review reports и
его fixtures обновлены вместе с основной схемой.

## Breadcrumb через shadcn/ui

Текущая Panel имеет `aria-current="page"`, предыдущие доступны с клавиатуры.
Новые зависимости не потребовались.
