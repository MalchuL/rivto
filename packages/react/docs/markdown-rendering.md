# Markdown rendering and live block size

`MarkdownContent` uses two representations of the same persisted block
content:

- `.markdown-editor` is the raw `contenteditable` Markdown source.
- `.markdown-preview` is the presentation generated by `react-markdown`.

The two elements occupy the same CSS Grid cell:

```css
.markdown-content {
  display: grid;
}

.markdown-editor,
.markdown-preview {
  grid-area: 1 / 1;
}
```

CSS Grid gives the shared container enough space for the larger representation.
This prevents headings, lists, tables, and other formatted content from
overlapping the following block.

## Why the block changes size while typing

Typing updates the block through the following path:

1. The raw `contenteditable` emits an `input` event.
2. `useBlockTextEditing` persists its plain-text content through the editor.
3. The editor revision rerenders `MarkdownContent`.
4. `react-markdown` renders a new preview from the latest source.
5. CSS Grid recalculates the height needed by the editor and preview.

The preview is hidden while the editor has focus:

```css
.markdown-content:focus-within .markdown-preview {
  visibility: hidden;
}
```

`visibility: hidden` hides painting but deliberately keeps the preview in
layout. Consequently, formatted content can adjust the block height immediately
while it is being typed. This avoids a size jump when focus leaves the block.
The raw editor can also grow naturally when text wraps or contains new lines.

Markdown remains presentation only. Parsing does not create blocks or modify
the document hierarchy.

## Opting out of preview-driven live sizing

Applications that prefer the block to use only raw-editor geometry while
focused can load this override after `@chulane/rivto-react/styles.css`:

```css
.markdown-content:focus-within .markdown-preview {
  display: none;
}
```

The formatted preview will then re-enter layout after blur, so the block may
change height at that moment. This does not prevent the raw editor itself from
growing as its text wraps.

To constrain editing height as well, an application can add a scrolling limit:

```css
.markdown-content:focus-within {
  max-height: 12rem;
  overflow: auto;
}
```

These are theme-level choices; no editor or block implementation changes are
required.
