# store

Store определяет ключевые операции над документом и его хранение в оперативной памяти. Важно понимать, что он не определяет финальную структуру блоков, а лишь обобщенные операции с документом, вроде добавления блоков, удаление, их получение, дополнительные свойства и прочее. Мы не учитываем то. Однако тут важно выделить следующие пункты, что все-таки зафиксировано в модели.

- 2 Формы отображения, в виде **блоков** и в виде **непрерывного канваса**
- Типы данных: Визуальные элементы на канвасе, блоки, линки, данные плагинов
- Однако блоки и элементы - это разные, непересекающиеся объекты. Для того, чтобы блоки можно было использовать как элементы (но не наоборот) мы создаем отдельный тип элементов, содержащий блоки внутри edgeless режима. Обратное тоже допустимо и необходимо лишь написать плагин для этого. 

Я постарался сделать архитектуру такой, чтобы ее можно было расширить для практических задач. Однако есть ограничения, вроде 2 режимов отображений и практической невозможностью расширения на чистый plain текст редактор, для этих задач лучше использовать другие фреймворки

## Document Model

Модель документа явно определяет то, какие типы данных мы можем поддерживать.

Как было сказано ранее он поддерживает свою структуру данных, которая затем используется в приложении. Это связано со спецификой некоторых операций, вроде буфера обмена, выделения текста/объектов

## CRTD

**CRDT** (Conflict-free Replicated Data Type) — это **конфликтно-бесплатный тип данных для репликации**. Это специальная структура данных в программировании, которая позволяет нескольким пользователям одновременно изменять информацию на разных устройствах без согласования с центральным сервером. Все изменения автоматически объединяются так, что в итоге на всех устройствах данные становятся абсолютно одинаковыми.

Документная модель явно использует эти типы и оборачивает для простого использования их в виде явных JS типов, чтобы не было необходимости манипулировать внутренними типами данных.

Помимо всего этого CRDT определяет свой документ, его сериализацию/десереализацию, undo/redo операции и провайдеры для синхронизации а также события, связанные с его изменением, чтобы все слушатели могли получить изменения
